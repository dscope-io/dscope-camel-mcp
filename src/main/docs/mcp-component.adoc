The MCP component provides integration with the https://modelcontextprotocol.io[Model Context Protocol] (MCP),
enabling Apache Camel routes to communicate with AI agents using the JSON-RPC 2.0 protocol.

== Producer

The producer sends MCP JSON-RPC 2.0 requests to remote MCP servers or local Camel routes. Supported methods include:

* `initialize` – Initialize an MCP session
* `ping` – Health check ping
* `tools/list` – List available tools
* `tools/call` – Invoke a specific tool
* `resources/list` – List available resources
* `resources/read` – Read a specific resource

Producer dispatch is selected by endpoint URI structure:

* `mcp:camel:<camel-endpoint-uri>` – local in-process Camel route dispatch
* `mcp:http://...` / `mcp:https://...` – remote JSON transport dispatch

Use the URI prefix `camel:` after `mcp:` to target local in-process routes.

Per-message method override is supported via header `CamelMcpMethod`.

For Java callers, `io.dscope.camel.mcp.McpClient` provides helper methods such as
`pingResult(...)`, `toolsListResult(...)`, `pingResultJson(...)`, and `toolsListResultJson(...)`
to return MCP `result` payloads as either raw objects or `JsonNode`.

== Consumer

The consumer exposes an HTTP (or WebSocket) endpoint that acts as an MCP server,
receiving JSON-RPC 2.0 requests from MCP clients (e.g., AI agents).

The consumer sets the following exchange properties:

* `mcp.jsonrpc.method` – The JSON-RPC method name
* `mcp.jsonrpc.id` – The JSON-RPC request id
* `mcp.tool.name` – The tool name (for `tools/call` requests)

== Protocol Revision Support

=== MCP Events

The local `1.5.0` build includes reusable webhook support following
https://developers.openai.com/plugins/build/mcp-events[the official MCP Events contract].
Use `McpEventsProcessor(McpEventsProvider)` for `events/list`, `events/subscribe`,
and `events/unsubscribe`. Enable discovery in any route with
`McpServerDiscoverProcessor(true)`, or register one provider in the Camel registry
for automatic consumer capability/dispatch. Application providers own authorization,
schema validation, subscription identities and persistent state.

`McpWebhookClient.verify(url, subscriptionId, secret)` verifies a signed challenge;
`send(url, subscriptionId, secret, previousSecret, event)` returns the HTTP status.
Callbacks use Standard Webhooks HMAC SHA256 and exact serialized bytes. HTTPS,
public IPv4/IPv6 address validation and pinning, no redirects, a ten-second deadline
and 256 KiB body limits apply to verification and delivery. Callback failures use
`McpCallbackException` with code `-32015` and categorized `data.reason`.
See `docs/mcp-events.md` for signatures, provider responsibilities and retry semantics.

=== Core protocol

The artifact version (`1.5.0`) is independent of the MCP protocol revision. The
component retains its legacy `2025-06-18` behavior by default. For Streamable HTTP
clients, set the Camel global option `mcp.http.protocolVersion` or JVM system
property `CamelMcpProtocolVersion` to `2026-07-28` to opt into the modern
per-request protocol.

Modern producer requests include `params._meta` with the protocol version and
client capabilities, plus the required `MCP-Protocol-Version` and `Mcp-Method`
headers. Requests to `tools/call`, `resources/read`, and `prompts/get` also send
`Mcp-Name`; values requiring encoding use the MCP Base64 sentinel format.
Modern consumer requests are checked for metadata/header consistency and
unsupported versions return MCP error `-32022` with `supported` and `requested`
versions. The consumer handles `server/discover` directly and advertises only the
implemented `tools` and `resources` primitives. Its discovery response includes
cache metadata. Built-in JSON-RPC response processors and JSON-RPC map responses
from user routes include `resultType: "complete"` and server identity metadata.

HTTP consumers allow requests without an `Origin` header. If an `Origin` header is
present, it must match an entry in the comma-separated `httpAllowedOrigins`
endpoint option, for example
`mcp:http://127.0.0.1:3000/mcp?httpAllowedOrigins=https://agent.example`.
HTTP allowlist falls back to `allowedOrigins` when `httpAllowedOrigins` is empty.
The default permits HTTP localhost and 127.0.0.1 origins on local ports. Origins
are parsed as URIs; credentials, paths, queries and fragments are rejected.
The component does not provide HTTP authorization; deployments must enforce
authorization in their hosting environment.

Initialization and `ping` remain available to legacy clients but are not exposed
for `2026-07-28`. The modern protocol is currently supported only over
Streamable HTTP; the component's WebSocket transport remains legacy. Modern
`subscriptions/listen` requests are delegated to the route, which must return an
SSE string, byte array, or `InputStream`; the producer exposes the remote stream
as an `InputStream`. Servers must ensure their stream implementation stops
producing when its consumer closes the connection. Multi-round-trip input
requests are passed through: the producer returns `input_required` result fields
as part of `McpResponse`, and on retry it forwards `inputResponses` and
`requestState` supplied in the request parameter map. The consumer exposes retry
values as `mcp.jsonrpc.inputResponses` and `mcp.jsonrpc.requestState` exchange
properties while retaining the existing tool-arguments message body. Server
routes remain responsible for fulfilling input requests and deciding whether
to retry; the component does not implement client UI or automatically execute
the requested client actions. Before returning an `input_required` result, the
consumer checks that each requested client action is supported by the
capabilities declared in that request's `_meta`.

The modern producer defaults `io.modelcontextprotocol/clientCapabilities` to
an empty object. Clients that can fulfill MRTR inputs must declare their
capabilities in the input parameter map's `_meta` field. For example:

[source,java]
----
Map.of(
    "name", "deploy",
    "arguments", Map.of("environment", "test"),
    "_meta", Map.of(
        "io.modelcontextprotocol/clientCapabilities",
        Map.of("elicitation", Map.of("form", Map.of()))))
----

Core notification delivery outside the subscription stream, SSE response streams
for ordinary request methods, and parameter-to-header mappings remain unsupported.
The optional MCP Events extension has separate signed HTTPS webhook support and
is advertised only when configured.
Existing Apps Bridge behavior is also not advertised as a modern protocol
capability.

=== Issue #6 feature status

This table describes the implementation status of the requirements tracked by
https://github.com/dscope-io/dscope-camel-mcp/issues/6[issue #6]. It is a
component status summary, not a claim of complete MCP `2026-07-28` conformance.

[cols="1,1,3",options="header"]
|===
|Area |Status |Current behavior and limitation

|Protocol revision and legacy compatibility
|Implemented
|The wire revision `2026-07-28` is opt-in; the component artifact is version `1.5.0`, and legacy `2025-06-18` remains the default. The modern HTTP consumer rejects unsupported or inconsistent version metadata instead of silently selecting a version.

|Discovery and HTTP request validation
|Partial
|`server/discover` is handled directly and reports the supported revisions, server identity, and `tools`/`resources` capabilities. Required modern HTTP headers, request metadata, `Mcp-Name` encoding, and configured Origin checks are validated. Discovery capability reporting and route coverage do not yet represent every MCP primitive implemented by user routes.

|Modern result fields and cache hints
|Implemented for component-decorated results
|Built-in response processors and JSON-RPC responses returned by consumer routes receive `resultType` and server identity metadata. Cacheable modern results receive or validate `ttlMs` and `cacheScope`. Arbitrary response shapes outside the component's recognized JSON-RPC/result forms are not normalized.

|Multi Round-Trip Requests (MRTR)
|Partial
|Producer requests can carry caller-supplied `inputResponses` and `requestState`; consumer routes can read them from `mcp.jsonrpc.inputResponses` and `mcp.jsonrpc.requestState`. The consumer validates server-issued input request shapes and checks declared client capabilities, including supported elicitation modes. The component does not fulfill input requests, provide client UI, or automatically retry a request; application routes and callers own that workflow.

|Subscriptions and streamed responses
|Partial
|Modern `subscriptions/listen` is routed to the application and supports an SSE response stream. The component does not manage the subscription lifecycle, emit change notifications independently of that response stream, handle cancellation end-to-end, or provide SSE responses for ordinary request methods.

|Parameter-to-header mapping and authorization
|Not implemented by the component
|`x-mcp-header`-style parameter mapping is not implemented. HTTP authorization must be enforced by the application or hosting environment.

|Optional MCP Events webhook extension
|Reusable support implemented
|The component parses `events/list`, `events/subscribe`, and `events/unsubscribe` for protocol `2026-07-28`, provides provider dispatch and optional discovery capability, and verifies/delivers signed HTTPS webhooks. Application providers own authorization, schema validation, subscription identity, persistence, expiration, replay, retry and rotation windows. See MCP Events below.

|WebSocket with `2026-07-28`
|Not implemented
|The modern per-request protocol support applies to Streamable HTTP. WebSocket continues to use the component's legacy behavior.
|===

For the upstream protocol definition, see the
https://github.com/modelcontextprotocol/modelcontextprotocol/tree/main/docs/specification/2026-07-28[official MCP `2026-07-28` specification]
and its
https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/changelog.mdx[changelog].
The Events extension requires a separate authoritative contract before it can
be documented as supported or implemented.

== Examples

=== Producer – Opt in to the modern protocol

The protocol revision is selected globally; the endpoint URI and method stay
unchanged. The default remains `2025-06-18`.

[source,java]
----
camelContext.getGlobalOptions().put("mcp.http.protocolVersion", "2026-07-28");
from("direct:discover")
    .setBody(constant(Map.of()))
    .to("mcp:http://localhost:8080/mcp?method=server/discover");
----

=== Producer – Call a Tool

[source,yaml]
----
- from:
    uri: "timer:callTool?repeatCount=1"
    steps:
      - setBody:
          constant: '{"name":"echo","arguments":{"message":"hello"}}'
      - unmarshal:
          json: {}
      - to: "mcp:http://localhost:8080/mcp?method=tools/call"
      - log: "${body}"
----

=== Producer – Local Camel MCP Service

[source,java]
----
from("direct:start")
    .setBody(constant(Map.of("clientInfo", Map.of("name", "local-client", "version", "1.0.0"))))
    .to("mcp:camel:direct:localMcpService?method=initialize")
    .log("${body}");
----

=== Producer – Remote vs Local (YAML)

Remote MCP producer route:

[source,yaml]
----
- route:
        id: remote-mcp-client
        from:
            uri: "direct:remoteMcp"
            steps:
                - setBody:
                        constant:
                            clientInfo:
                                name: "camel-client"
                                version: "1.0.0"
                - to:
                        uri: "mcp:http://localhost:8080/mcp?method=initialize"
                - setBody:
                        simple: "${body[result]}"
----

Local MCP producer route + local service route:

[source,yaml]
----
- route:
        id: local-mcp-client
        from:
            uri: "direct:localMcpClient"
            steps:
                - setBody:
                        constant:
                            probe: true
                - to:
                        uri: "mcp:camel:direct:localMcpService?method=ping"
                - setBody:
                        simple: "${body[result]}"

- route:
        id: local-mcp-service
        from:
            uri: "direct:localMcpService"
            steps:
                - setBody:
                        simple: |
                            {
                                "jsonrpc": "2.0",
                                "id": "${body[id]}",
                                "result": {
                                    "method": "${body[method]}",
                                    "pong": true,
                                    "local": true
                                }
                            }
                - unmarshal:
                        json:
                            library: Jackson
----

=== Consumer – Expose an MCP Server

[source,java]
----
from("mcp:http://0.0.0.0:3000/mcp")
    .choice()
        .when(exchangeProperty("mcp.jsonrpc.method").isEqualTo("tools/list"))
            .setBody(constant("{\"tools\":[]}"))
        .when(exchangeProperty("mcp.jsonrpc.method").isEqualTo("tools/call"))
            .process(exchange -> { /* handle tool call */ })
    .end();
----
